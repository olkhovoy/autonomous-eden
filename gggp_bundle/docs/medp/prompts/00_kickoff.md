# 00. Kickoff — восстановление контекста новой сессией

Этот шаблон превращает любую новую сессию (любой модели) в участника
MEDP-цикла, используя **только** содержимое репо. Chat-state не
требуется и не должен использоваться.

---

## Инструкция для сессии

Ты — участник MEDP-процесса для проекта `gggp_bundle`. Твоя задача —
восстановить контекст и предложить следующее действие строго по
протоколу.

### Шаг 1. Прочитать обязательные файлы в этом порядке

1. `gggp_bundle/docs/medp/ROOT.md` — протокол, словарь, дерево форков, гейты.
2. `gggp_bundle/docs/medp/log.jsonl` — журнал событий (источник истины).
3. Если в журнале последняя запись касается конкретной ветки `<id>`:
   - `gggp_bundle/docs/medp/branches/<id>/plan.md`
   - `gggp_bundle/docs/medp/branches/<id>/checkpoints.md`
   - `gggp_bundle/docs/medp/branches/<id>/postmortem.md` (если существует)
4. `gggp_bundle/docs/SEMIOTIC-HYPERCUBE.md` — исходный концепт.
5. `gggp_bundle/docs/EMBEDDING_GGGP.md` — текущий вектор-фенотип.
6. `gggp_bundle/docs/UMC_HYPOTHESES.md` — критерии NC1..NC4.

### Шаг 2. Проверить git-состояние

- `git log --grep='^medp:' --oneline -20` — последние MEDP-события.
- `git branch --list 'medp/*'` — активные ветки.
- `git tag -l 'medp/*'` — промоушны и архивы.
- Убедиться, что текущая HEAD совместима с последней записью `log.jsonl`.
  При расхождении → §Шаг 5.

### Шаг 3. Собрать сводку состояния

Ответ должен содержать ровно эти разделы (без воды):

1. **Активная ветка** — `branch_id` или `root`.
2. **Последний гейт** — id, result, value, threshold, ts.
3. **Оставшийся бюджет** — dev_h и compute_h (на основании
   `{event:"branch_start"}` минус реально потраченное время).
4. **Следующий гейт** — id, deadline, метрика, порог.
5. **Потенциальные риски** — один-два пункта из опыта postmortem'ов
   предыдущих веток, если они есть в `branches/*/postmortem.md`.

### Шаг 4. Предложить следующее действие

Одно из:

- Продолжить активную ветку до следующего гейта (§9.2 ROOT.md).
- Оценить текущий гейт (открыть `prompts/01_evaluate_gate.md`).
- Выполнить backtrack (открыть `prompts/02_backtrack.md`).
- Промоутить ветку (§9.6 ROOT.md).
- Запросить новый форк (открыть `prompts/03_fork.md`).
- Инициировать meta-backtrack (§10 ROOT.md) — только при исчерпании всех резервных ветвей.

Ожидать подтверждения пользователя перед исполнением. Запрет на
самовольный merge / force-push / rebase веток `medp/*` (§9 ROOT.md).

### Шаг 5. При расхождении между HEAD и log.jsonl

- `log.jsonl` — источник истины (§5 ROOT.md).
- `plan.md` и `postmortem.md` могут быть пересозданы из журнала.
- Сообщить пользователю о расхождении с указанием первой расходящейся записи.
  Не исправлять автоматически.

---

## Рамка ответа (жёсткая)

```
## MEDP state

- Активная ветка: <id>
- Последний гейт: <gate_id> <result> value=<x> threshold=<y> at <ts>
- Бюджет: dev_h_left=<a>, compute_h_left=<b>
- Следующий гейт: <id>, deadline=<t+Δ>, метрика=<...>, порог=<...>
- Риски: <пункт или "—">

## Предлагаемое следующее действие

<один из вариантов §Шаг 4>
<обоснование в 1–3 предложения, со ссылкой на пункт ROOT.md или запись log.jsonl>

## Ожидаю подтверждения от пользователя перед исполнением.
```

Любой другой формат ответа при kickoff — нарушение протокола.
