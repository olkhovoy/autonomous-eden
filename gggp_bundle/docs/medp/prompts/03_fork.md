# 03. Fork — предложение новой развилки

Вызывается, когда в ходе работы обнаруживается **новое** техническое
решение, которое не было предусмотрено в §6 ROOT.md, и есть ≥2
сопоставимых альтернатив. Результат — формальный fork с добавлением
резервных ветвей в `ROOT.md` + запись в журнал.

---

## Когда запрещено открывать форк

- Если выбор между альтернативами уже сделан в ROOT.md / предыдущем
  fork'е. Нельзя «забыть» и переиграть.
- Если одна из альтернатив — «просто подкрутить параметры». Параметры
  это не форк, это `threshold_adjusted` или работа внутри ветки.
- Если все альтернативы ведут к одному и тому же фитнесу
  (нет сопоставимых utilities) — это не форк, это эквивалентный
  рефакторинг.

## Вход

- `origin_branch` — ветка, в которой возникла потребность в форке.
- `decision_point` — одна фраза, описывающая, какой выбор стоит.
- `alternatives[]` — минимум 2, каждая:
  - `label` (короткий слаг, напр. `linear`, `gggp_tree`, `prompt`)
  - `cost_dev_h` — оценка трудозатрат
  - `cost_compute_h` — оценка потребных вычислений
  - `expected_utility` — ожидаемое влияние на `F` (0..1 или «high/med/low» с обоснованием)
  - `risk` — основной риск
  - `required_deps` — новые крейты / модели / датасеты

## Алгоритм

1. Проверить §Когда запрещено. Если попадает — отклонить форк,
   предложить правильный шаблон (`threshold_adjusted` / работа внутри ветки).
2. Назначить `new_fork_id` = `F<N>` (следующий номер; см. существующие F0..F3 в ROOT.md §6).
3. Для каждой альтернативы сгенерировать резервный `branch_id`
   (`A<k>`), учитывая уже занятые номера.
4. Добавить записи в таблицу §6.5 ROOT.md (резерв) с триггером активации
   = «`origin_branch` провалил гейт `<gate_id>`» или «origin_branch
   promote + требуется независимая проверка <гипотеза>».
5. Записать в `log.jsonl`:
   ```
   {"ts":"<ISO>","event":"fork_proposed","branch":"<origin_branch>","author":"<who>","new_fork_id":"F<N>","alternatives":[{...},{...}],"rationale":"..."}
   ```
6. Коммит: `medp: fork F<N> proposed at <origin_branch>`.
7. **Не начинать работу по альтернативам.** Они становятся резервом,
   активируемым только по триггеру.

## Рамка ответа

```
## Fork proposal F<N>

- Origin branch: <origin_branch>
- Decision point: <одна фраза>

## Альтернативы

| label | cost_dev_h | cost_compute_h | expected_utility | risk | required_deps |
|---|---|---|---|---|---|
| <a> | ... | ... | ... | ... | ... |
| <b> | ... | ... | ... | ... | ... |

## Триггеры активации

- <branch_id_for_a>: <условие>
- <branch_id_for_b>: <условие>

## Записи

ROOT.md diff (секция §6.5 Reserve):
<markdown-фрагмент>

log.jsonl append:
<JSON-строка>

commit message:
<строка>

## Ожидаю подтверждения перед применением.
```

После применения форка — `origin_branch` продолжает работу как была.
Резервные ветки активируются только по своим триггерам.
