# Evolutionary Engine: фокус, метрики, план работ (черновик)

Документ фиксирует продуктовый фокус и метрики успеха для самостоятельного движка
Evolutionary Engine, а также краткий план этапов. Основа — PoC GGGP на Rust.

---

## 1) Продуктовый фокус

**Цель верхнего уровня:** Evolutionary Engine как самостоятельный продукт (библиотека + SDK + демо).

**Что такое ядро движка (MVP):**

- Грамматически направляемый GP (GGGP) с поддержкой параметризованных чисел.
- Стабильный интерфейс: вход = grammar + genotype + optional dataset, выход = phenotype + fitness.
- Детерминируемый RNG (seed) и воспроизводимость результатов.
- Поддержка генетических операторов (crossover/mutation/selection).
- Набор примеров, покрывающих разные классы задач.

**Не входит в MVP:** сложная торговая платформа, реальный брокерский интегратор, UI.

---

## 2) Метрики успеха

### 2.1 Производительность

- **Throughput:** оценок fitness в секунду (eval/s) для типовых задач.
- **Latency:** время генерации результата (best-of-run) при заданном бюджете.
- **Memory:** пик потребления памяти на типовой задаче.

### 2.2 Качество решений

- **Best fitness:** на каждом демо есть измеримый target (error/MSE, correctness, similarity).
- **Convergence:** скорость улучшения на N поколениях.
- **Stability:** разброс результата при разных seed (variance).

### 2.3 Воспроизводимость

- **Determinism:** одинаковый seed → тот же результат.
- **Round-trip:** грамматика/хромосома воспроизводят тот же код/глиф.

### 2.4 Трек «вне трейдинга»

- **Time-to-demo:** время до «вау» эффекта в прототипах.
- **Effort-to-demo:** стоимость реализации демо vs рыночный эффект.

## 3) План этапов (скелет)

**Этап A — ядро и метрики**

- Зафиксировать API границы (данные, grammar, fitness callback).
- Встроить профилирование и сбор базовых метрик.
- Закрыть критичные edge cases (grammar errors, invalid chromosomes).

**Этап B — демо-линейка**

- Отобрать 2–3 демо задачи по критериям.
- Первым демо взять Prompt Breeding (локально на Ollama, детерминированный fitness).
- Сделать pipeline для каждого демо (данные → грамматика → фитнес → отчёт).
- Довести визуализацию и отчётность (SVG/графики/таблицы).

**Этап C — SDK/ABI фундамент**

- Стабильный C ABI (ffi-слой).
- Базовые биндинги (Python/JS/Go — зависит от приоритета).
- Документация и примеры.

**Этап D — EVoS**

- OpenAPI/JSON-RPC спецификация.
- Модель задач, изоляция, очереди, мониторинг.

---

## 4) Риски и ответы

- **Перфоманс узких мест** → раннее профилирование + bench.
- **Сложность демо** → жёсткие критерии отбора + ограничение scope.
- **Детерминизм** → строгий контроль seed/версий.
