# Демо‑кандидаты для Evolutionary Engine

Цель: выбрать 2–3 «вау» демо задачи, которые трудны для brute‑force, но
хорошо решаемы GGGP; просты в реализации по сравнению с торговой платформой.

---

## 1) Критерии отбора

1. **Формализуемый fitness** — прозрачная метрика качества.
2. **Высокая комбинаторика** — brute force быстро становится невозможен.
3. **Проверяемость** — можно жёстко проверить correctness/приближение.
4. **Визуализация** — результат понятен и «вау».
5. **Простота реализации** — минимальная инфраструктура.
6. **Скорость оценки** — fitness должен считаться быстро.

---

## 2) Длинный список кандидатов

1. **Symbolic Regression (формула по данным)**
2. **Sorting Networks (синтез сетей сортировки)**
3. **Boolean Circuit Synthesis (логические схемы по truth table)**
4. **Regex Synthesis (строки → регулярка)**
5. **Glyph/Logo Evolution (глифы/логотипы по target)**
6. **Small DSL Program Synthesis (мини‑алгоритмы по I/O)**
7. **Control Policy for Toy System (управление простым симулятором)**
8. **Graph Layout/Embedding Optimization (минимизация пересечений)**
9. **Constraint Puzzle (mini‑SAT, n‑queens)**
10. **Audio Pattern Synthesis (мелодия по target спектру)**
11. **Agent Auto‑Synthesis (AI‑агенты под задачу)**
12. **Prompt Breeding (эволюция промптов)**
13. **Micro‑NAS (эволюция маленьких архитектур)**
14. **Protocol Zero (эволюция смарт‑контрактов)**

---

## 3) Рекомендуемые демо (основной трек)

### 3.1 Prompt Breeding (эволюция промптов)

**Задача:** автоматическая генерация промптов, которые устойчиво решают заданный класс задач.

- **Вход:** набор тест‑кейсов + строгий формат ответа (JSON/схема).
- **Грамматика:** структура промпта (Role/Context/Constraints/Examples/Output Schema).
- **Хромосома:** конкретные формулировки и блоки.
- **Fitness:** валидность JSON + точность + штраф за длину + стоимость токенов.
- **Выход:** лучший промпт + отчёт качества + статистика устойчивости.
- **Вау‑эффект:** «идеальный промпт найден эволюцией».
- **Сложность реализации:** низкая (локально на Ollama).

**Гейтинг:** 100% валидность формата + точность выше порога на unseen тестах.

### 3.2 Agent Auto‑Synthesis (AI‑агенты под задачу)

**Задача:** автогенерация и адаптация «агентов» как особей GGGP под конкретную задачу.

- **Вход:** библиотека примитивов (actions/tools), набор задач или тест‑кейсов.
- **Грамматика:** DSL для политики агента (if/then, tool‑call, memory slots).
- **Fitness:** результат по тест‑кейсам + штраф за сложность + устойчивость.
- **Выход:** минимальный агент‑скрипт + отчёт по задачам.
- **Вау‑эффект:** «агент рождается под задачу» + показ кроссоверов.
- **Сложность реализации:** средняя (можно начать с простого песочника).

**Гейтинг:** стабильное прохождение тест‑кейсов на unseen наборах.

### 3.3 Glyph/Logo Evolution (Glagolitic-inspired)

**Задача:** генерация глифов/логотипов под визуальные цели.

- **Вход:** target shapes (SVG/bitmap), набор архетипов.
- **Грамматика:** turtle‑DSL (F/L/R/Z), параметры длины/углов.
- **Fitness:** визуальная близость + замкнутость + симметрия + сложность.
- **Выход:** SVG‑галерея + статистика прогресса.
- **Вау‑эффект:** наглядная эволюция форм.
- **Сложность реализации:** низкая (частично уже есть).

**Гейтинг:** совпадение по similarity выше порога + устойчивость по seed.

## 4) Дополнительные демо (вторая волна)

### 4.1 Symbolic Regression (формула по данным)

**Задача:** найти аналитическую формулу, аппроксимирующую заданную зависимость.

- **Вход:** таблица (x → y), выбранные базовые функции.
- **Грамматика:** арифметика + sin/cos/exp/log + константы.
- **Fitness:** MSE + штраф за сложность (размер дерева).
- **Выход:** формула + график ошибки + сравнение с baseline.
- **Вау‑эффект:** «движок нашёл закон».
- **Сложность реализации:** низкая.

**Гейтинг:** MSE < threshold на тестовых данных, формула компактна.

### 4.2 Sorting Networks

**Задача:** эволюция последовательности comparator‑операций для сортировки N элементов.

- **Вход:** N (например 6 или 8), ограничение глубины/размера.
- **Грамматика:** DSL для comparator(i, j) и последовательностей.
- **Fitness:** correctness на всех входах + штраф за число компараторов и глубину.
- **Выход:** схема сети + статистика.
- **Вау‑эффект:** строгая корректность + компактность.
- **Сложность реализации:** средняя.

**Гейтинг:** 100% корректность на полном наборе входов; минимизация размера.

### 4.3 Micro‑NAS (The Unitary Architect)

**Задача:** эволюция маленьких нейро‑архитектур с рекурсивными связями.

- **Вход:** синтетическая задача + краткий цикл обучения (1–5 минут).
- **Грамматика:** слои/связи (Linear, Attention, Recurrence, Skip).
- **Fitness:** loss + штраф за размер + устойчивость.
- **Выход:** модель‑архитектура + отчёт.
- **Сложность реализации:** высокая (но контролируемая на микро‑задачах).

**Гейтинг:** улучшение loss на тесте при ограничении размера/времени.

### 4.4 Protocol Zero (смарт‑контракты)

**Задача:** эволюция контрактов/атак в песочнице (Solidity/Rust).

- **Fitness:** компиляция + безопасность/доходность + газ.
- **Риск:** правовые и этические ограничения, сложная инфраструктура.

**Гейтинг:** только после зрелости SDK и инфраструктуры.

## 5) Демонстрационные пайплайны (первый релиз)

### A) Prompt Breeding Pipeline

1. Определить тест‑кейсы и строгий JSON‑формат ответа.
2. Эволюция промптов по грамматике (Role/Context/Constraints/Examples).
3. Валидатор JSON + оценка точности (детерминированно).
4. Итог: лучший промпт + отчёт качества и стоимости токенов.

### B) Agent Auto‑Synthesis Pipeline

1. Определить песочницу: фиксированные tools и тест‑кейсы.
2. Эволюция политики агента (программа на DSL).
3. Логирование прогресса и лучших решений.
4. Итог: агент‑скрипт + отчёт по задачам + примеры crossover.

### C) Glyph Evolution Pipeline

1. Выбор 6–9 архетипов (глаголица).
2. Эволюция наборов глифов параллельно.
3. Итог: SVG‑галерея + метрики сходства.

---

## 6) Как это ляжет в SDK (будущий шаг)

Каждое демо оформляем одинаково:

- **Input:** grammar + dataset + fitness config
- **Run:** evolve(params)
- **Output:** best individual + report + artifacts

Так формируется «универсальный SDK‑контур» для внешних языков.
